## Item-by-item status

1. **Dirty worktree + Phase 1 commits — done.** Full suite green (344/0).
2. **POST_NOTIFICATIONS runtime ask — done** (`MainActivity.requestNotificationPermissionThenConnect`,
   chained after the VPN-permission grant; denial does not block connecting).
3. **Cleartext http:// subscription rejection — done** via `SubscriptionUrlPolicy` shared by
   `SubscriptionFetcher` (fetch), `ProfileImporter.importSubscriptionUrl` (direct import) and
   `LuxyVpnRepository.editSubscription` (edit). Public `http://` is rejected with the localized
   message "Subscription URL must use HTTPS" / «لینک اشتراک باید از نوع HTTPS باشد؛ نشانی‌های
   http ناامن هستند». Loopback hosts stay allowed so local panels keep working. The fetch
   propagates the policy reason instead of the generic "Could not update subscription".
4. **Room encryption — DEFERRED, needs your approval.** `docs/adr/0002-room-database-encryption.md`
   proposes SQLCipher (option B: Keystore-wrapped random passphrase + `SupportFactory`).
   Tradeoffs recorded there: +~15 MB native before ABI splits vs. plaintext DB on rooted
   devices; migration risk; licensing audit. **No code changed.**
5. **XrayEngine.stop() startLock blocking — done.** Bookkeeping stays under the lock;
   `stopLoop()` dispatches to a daemon executor; `start()`'s inline stale-core stop is
   hardened. Host tests pin bookkeeping/idle/executor-seam; the with-controller offload
   branch cannot run on the test JVM (no x86_64 `libgojni`) and is covered on-device.
6. **Always-On initial notification — done.** Idle always-on start maps to CONNECTING;
   pinned by `AlwaysOnNotificationTest` (asserts the posted foreground notification).
7. **ProxyProbe bounded executor — done.** `measureOutboundDelay` (blocking JNI that
   `withTimeoutOrNull` cannot interrupt) runs on a fixed 2-thread daemon pool
   (`measureDispatcher`, injectable); pool bound pinned by a test.
8. **autoUpdateHours periodic refresh — done, via AlarmManager (not WorkManager).**
   WorkManager is not in the offline dependency cache; `setAndAllowWhileIdle` needs no new
   dependency or permission. `SubscriptionRefreshScheduler` arms one alarm per timed
   subscription at `lastUpdatedAt + autoUpdateHours` (clamped ≥ +60 s); `autoUpdateHours <= 0`
   opts out. `SubscriptionRefreshReceiver` refreshes through `ProfileImporter` (safe while a
   tunnel is up) and re-arms; `SubscriptionBootReceiver` re-arms after reboot. Rescheduling
   hooks: app start, import/manage success, backup-restore success. `RECEIVE_BOOT_COMPLETED`
   added; both receivers `exported="false"`.

## Not applied — "Phase 4 polish items (#14–#18), skip #19"

The numbered list belonged to the older parity plan (`luxynet-v2fall-parity`): #14 in-app
updater, #15 QS tile/widget/boot autostart, #16 deep links, #17 i18n+RTL, #18 logs console.
In this minimal-client repo #16/#17 already ship (proxy deep links, fa/en RTL), and the boot
autostart part of #15 now exists (subscription boot receiver); the full V2Fall parity surface
(updater distribution channel, QS tile/widget, logs console) requires product decisions this
repo's plan does not contain. The item was therefore **recorded as not directly applicable
rather than guessed**; nothing was skipped silently. #19 (backup export/share) was already
partially present and per the plan remains out of scope.
